# Discord UX Redesign

## 목적

현재 프로젝트는 기능 자체는 성립하지만, 사용자 경험이 `슬래시 커맨드 입력 -> 단일 모달 -> 텍스트 응답`에 과도하게 의존한다.

이 문서의 목표는 프로젝트를 `명령어 중심 봇`이 아니라 `Discord 안에서 동작하는 네이티브 스터디 운영 앱`으로 재정의하는 것이다.

## 현재 문제

- 핵심 기능 진입점이 명령어 중심이라 초보 사용자가 기능을 발견하기 어렵다.
- 각 기능이 단발성 상호작용으로 끝나서 현재 상태를 한눈에 보기 어렵다.
- 버튼은 있으나 화면 구조가 정보 카드 수준으로 정리되어 있지 않다.
- 관리자 설정도 여전히 명령어 문법을 알아야 하는 느낌이 강하다.
- 매주 계획, 매일 인증, 리더보드가 하나의 연결된 흐름으로 보이지 않는다.

## 재설계 원칙

- 슬래시 커맨드는 보조 진입점으로만 둔다.
- 실제 사용 흐름은 `고정 홈 메시지`를 중심으로 설계한다.
- 한 화면에서 `현재 상태`, `다음 행동`, `빠른 이동`이 동시에 보여야 한다.
- 가능한 한 `메시지 갱신`으로 상태를 유지하고, 새 메시지 남발을 줄인다.
- 관리자와 일반 사용자의 흐름을 같은 UI 패턴으로 통일한다.
- Discord가 제공하는 네이티브 컴포넌트를 최대한 활용한다.

## 목표 UX

### 1. 홈 대시보드 중심

서버에 봇이 설치되면 스터디 전용 채널에 `스터디 홈` 메시지 하나를 생성하고 고정한다.

이 메시지는 다음 역할을 가진다.

- 이번 주 진행 상황 요약
- 오늘 해야 할 액션 안내
- 계획 작성/수정
- 인증 제출
- 리더보드 보기
- 내 현황 보기
- 관리자 설정 진입

### 2. 명령어 없는 기본 사용 흐름

일반 참여자 기본 흐름:

1. 고정된 `스터디 홈` 메시지를 연다.
2. `계획 작성` 또는 `오늘 인증` 버튼을 누른다.
3. 필요한 경우 모달 또는 선택 UI가 열린다.
4. 제출 후 동일한 홈 메시지 또는 개인용 응답이 갱신된다.

관리자 기본 흐름:

1. `스터디 홈` 메시지에서 `서버 설정` 버튼을 누른다.
2. 설정 카드를 열거나 모달을 연다.
3. 채널, 시간, 타임존을 GUI 형태로 변경한다.

### 3. 기능 흐름의 앱화

기존:

- `/주간계획`
- `/인증`
- `/리더보드`
- `/설정`

변경:

- `스터디 홈 카드`
- `이번 주 계획 카드`
- `오늘 인증 카드`
- `내 진행 현황 카드`
- `리더보드 카드`
- `관리자 설정 카드`

## 핵심 화면 제안

### 화면 A. 스터디 홈

포함 정보:

- 이번 주 기간
- 전체 참여자 수
- 계획 작성 완료 인원
- 오늘 인증 완료 인원
- 내 현재 상태
- 빠른 액션 버튼

주요 액션:

- `계획 작성`
- `오늘 인증`
- `내 현황`
- `리더보드`
- `새로고침`
- `서버 설정` (관리자 전용)

### 화면 B. 계획 카드

포함 정보:

- 내 이번 주 목표
- 목표 인증 횟수
- 현재 누적 인증 수
- 수정 가능 여부

주요 액션:

- `계획 작성`
- `계획 수정`
- `지난 계획 참고`

### 화면 C. 인증 카드

포함 정보:

- 오늘 인증 가능 여부
- 이미 인증했는지 여부
- 이번 주 누적 인증 수
- 마지막 인증 내용 요약

주요 액션:

- `오늘 인증`
- `내 인증 현황`

### 화면 D. 리더보드 카드

포함 정보:

- 상위 N명
- 내 순위
- 내 달성률
- 오늘 기준 전체 진행률

주요 액션:

- `상위 10명`
- `내 주변 순위`
- `이번 주 통계`

### 화면 E. 관리자 설정 카드

포함 정보:

- 타임존
- 계획 리마인더 채널/시간
- 인증 리마인더 채널/시간
- 리더보드 채널/시간

주요 액션:

- `채널 변경`
- `시간 변경`
- `타임존 변경`
- `테스트 발송`

## 커맨드 정책

커맨드를 없애지는 않는다. 다만 역할을 축소한다.

- `/홈`: 홈 메시지 생성 또는 다시 띄우기
- `/주간계획`: 홈 진입 실패 시 대체 진입점
- `/인증`: 홈 진입 실패 시 대체 진입점
- `/리더보드`: 빠른 조회용 대체 진입점
- `/설정`: 관리자용 백업 진입점

즉, 커맨드는 메인 UX가 아니라 `fallback`이어야 한다.

## 단계별 도입 계획

### Step 1. 홈 메시지 도입

- `스터디 홈` 메시지 생성
- 버튼 기반 주요 액션 연결
- 명령어는 유지

### Step 2. 카드형 메시지 구조 전환

- 홈/리더보드/설정 응답을 모두 카드형 메시지로 재구성
- 정보 요약과 액션을 같은 메시지에 배치

### Step 3. 다단계 흐름 도입

- 설정 변경, 계획 작성, 인증 제출을 단계형 wizard로 개선
- 메시지 갱신과 모달을 섞어서 사용

## 기대 효과

- 명령어 학습 비용 감소
- 고정 메시지 중심으로 진입성이 좋아짐
- 봇이 아니라 앱처럼 느껴짐
- 반복 사용성이 좋아짐
- 관리자 설정 실수 감소
