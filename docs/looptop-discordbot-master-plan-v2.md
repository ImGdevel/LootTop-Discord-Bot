# LoopTop DiscordBot Master Plan V2

## 1. 프로젝트 개요

### 프로젝트명

- 표시 이름: `LoopTop DiscordBot`
- 기술 식별자: `looptop-discord-bot`

### 프로젝트 목적

LoopTop DiscordBot은 디스코드 스터디 서버 안에서 다음 운영 흐름을 자동화하는 채널 기반 서버리스 스터디 운영 시스템이다.

- 주간 목표 수립
- 일일 인증 제출
- 자동 주간 리더보드 집계
- 채널별 역할 분리 기반 운영

이 프로젝트는 `24시간 상주 Gateway 봇`이 아니라, `Discord를 UI로 사용하는 Cloudflare Workers 기반 앱`으로 구축한다.

## 2. 제품 비전

이 봇은 명령어를 외워야 하는 봇이 아니라, 디스코드 채널 구조 안에서 자연스럽게 동작하는 운영 앱이어야 한다.

핵심 원칙:

- 기능은 채널 역할에 따라 분리한다.
- 사용자는 버튼, 카드, 모달 중심으로 사용한다.
- 공개 기록은 공개 채널에 남기고, 입력 과정은 개인화된 상호작용으로 처리한다.
- 운영자는 별도 웹 대시보드 없이 디스코드 안에서 운영 가능해야 한다.

## 3. 최종 기술 선택

- Language: `TypeScript`
- Runtime: `Cloudflare Workers`
- Database: `Cloudflare D1`
- Scheduler: `Cloudflare Cron Triggers`
- Discord Integration: `Discord Application Interactions` + `Discord REST API`
- Deployment Tooling: `Wrangler`

선택 이유:

- 상시 서버가 필요 없다.
- Discord Interaction Webhook 구조와 잘 맞는다.
- 포럼 글, 쓰레드, 카드 메시지, 모달, 버튼 기반 UX 구현에 적합하다.
- Cron 기반 자동 생성 작업과 궁합이 좋다.

## 4. 채널 기반 제품 구조

### 4.1 권장 채널

길드별 권장 채널은 다음과 같다.

1. `#스터디-홈`
2. `#목표` (포럼 채널)
3. `#인증` (텍스트 채널)
4. `#리더보드` (포럼 채널)

### 4.2 각 채널의 역할

#### `#스터디-홈`

- 전체 기능의 메인 진입점
- 홈 대시보드 카드
- 목표/인증/리더보드/설정 이동

#### `#목표`

- 매주 생성되는 목표 포럼 글 보관
- 사용자별 목표 카드 게시

#### `#인증`

- 매일 생성되는 인증 쓰레드 보관
- 사용자별 인증 카드 게시

#### `#리더보드`

- 매주 생성되는 리더보드 포럼 글 보관
- 주간 랭킹 및 요약 게시

## 5. 핵심 Discord 제약과 대응

### 5.1 가능한 것

- 포럼 채널 내부에 주간 포럼 글 생성
- 텍스트 채널 내부에 일일 쓰레드 생성
- 버튼/셀렉트/모달 기반 상호작용
- 공개 카드 메시지 게시
- 사용자별 ephemeral 응답

### 5.2 직접 불가능한 것

- 사용자가 채널에 입장했을 때 자동으로 개인 UI를 띄우는 것
- HTML/CSS 수준의 자유로운 커스텀 UI
- 네이티브 멀티페이지 모달

### 5.3 대응 방식

- 공개 고정 메시지의 버튼 클릭을 개인 흐름 진입점으로 사용
- 카드 메시지 + 모달 + 메시지 갱신으로 wizard 구성
- 홈 채널을 두어 기능 발견성을 확보

## 8. 핵심 사용자 시나리오

### 시나리오 A. 주간 목표 작성

1. 매주 일요일 18:00에 `#목표` 포럼 채널에 새 주간 글 생성
2. 사용자가 글 안의 `내 목표 작성` 버튼 클릭
3. 시스템이 사용자별 목표 작성 여부 확인
4. 목표 작성 wizard 진행
5. 완료 시 사용자 목표 카드가 해당 포럼 글 안에 게시됨

### 시나리오 B. 일일 인증 제출

1. 매일 04:00에 `#인증` 채널에 새 인증 쓰레드 생성
2. 사용자가 `오늘 인증` 버튼 클릭
3. 시스템이 이번 주 목표를 바탕으로 동적 인증 폼 구성
4. 사용자가 일부 또는 전체 항목 인증 제출
5. 인증 카드가 해당 일일 쓰레드에 게시됨

### 시나리오 C. 추가 인증 제출

1. 사용자가 같은 날 다시 인증 버튼 클릭
2. 기존 기록은 유지됨
3. 새 인증이 추가 저장됨
4. 해당 일자의 누적 달성치에 합산됨

### 시나리오 D. 주간 리더보드 생성

1. 매주 월요일 00:00에 주간 집계 수행
2. `#리더보드` 포럼 채널에 새 글 생성
3. Top 3 / Bottom 3 / 전체 순위 카드 게시

## 9. 시스템 아키텍처

### 9.1 전체 흐름

1. Discord가 Interaction 요청을 Worker에 전달
2. Worker가 서명 검증
3. Interaction router가 command/component/modal 분기
4. Service layer가 비즈니스 로직 수행
5. D1 저장/조회
6. Discord REST API로 포럼 글, 쓰레드, 카드 메시지 게시
7. Cron Trigger가 예약 작업 수행

### 9.2 Interaction 응답 원칙

Discord Interaction은 3초 이내 최초 응답이 필요하므로 다음 패턴을 기본으로 사용한다.

1. 즉시 deferred 응답
2. 비즈니스 로직 수행
3. followup 또는 원본 메시지 수정

### 9.3 공개/개인 응답 정책

- 입력 확인, 오류, 내 상태: `ephemeral`
- 목표 카드, 인증 카드, 리더보드 카드: 공개 메시지

## 13. 비즈니스 규칙

### 목표 규칙

- MVP에서는 데일리 목표만 지원
- 한 사용자는 한 주에 하나의 목표 세트만 가진다
- 목표 항목은 여러 개 작성 가능
- 각 항목마다 인증 방식 지정 가능

### 휴식일 규칙

- 기본 휴식일은 토/일
- 사용자는 해제하거나 평일을 추가할 수 있다
- 휴식일은 미인증 실패 계산에서 제외

### 인증 규칙

- 목표 없이 인증 불가
- 인증은 해당 날짜의 쓰레드가 열려 있는 동안만 유효
- 같은 날 여러 번 제출 가능
- 마감 이후 인증은 차단

### 리더보드 규칙

- 주간 달성률 기준 정렬
- Top 3 / Bottom 3 산출
- 참여자는 목표를 작성한 사용자 기준
