# Discord Study Bot Planning

## 목적

스터디 운영을 관리하는 디스코드 봇을 만든다.

초기 MVP 기능:

- 매주 계획 세우기
- 매일 인증하기
- 주간 리더보드

## Discord 플랫폼 조사 결론

### Discord가 직접 제공하는 것

- 봇 계정과 앱 권한 체계
- 슬래시 커맨드
- 버튼, 셀렉트 메뉴, 모달 같은 상호작용 UI
- 서버/채널/유저 ID 기반 식별
- Gateway 이벤트 수신
- 봇 메시지 전송, 수정, DM 전송
- 상호작용 응답용 웹훅

### Discord가 직접 제공하지 않는 것

- 우리 서비스용 사용자별 장기 데이터 저장소
- 주간 계획/일일 인증/누적 통계의 영속 저장
- 매주 일요일 자동 정산을 위한 앱 내부 스케줄러
- 학습 규칙에 맞춘 달성률 계산 로직

즉, 봇은 입력과 알림의 창구이고, 실제 기록과 집계는 우리 애플리케이션이 별도로 저장하고 계산해야 한다.

## 핵심 질문에 대한 답

### 1. 개인 활동을 기록하고 기억할 수 있는가?

가능하다. 다만 **Discord가 저장해주는 것이 아니라 우리 서버가 저장**해야 한다.

- 짧게는 프로세스 메모리에 저장할 수 있다.
- 운영용으로는 SQLite, PostgreSQL 같은 DB를 둬야 한다.
- 메모리만 쓰면 재시작 시 데이터가 사라지므로 스터디 운영 봇에는 부적합하다.

### 2. 주간 계획과 일일 인증을 Discord 안에서 받을 수 있는가?

가능하다.

- 주간 계획: 슬래시 커맨드 + 모달
- 일일 인증: 슬래시 커맨드, 버튼, 모달, 특정 채널 메시지, 반응 이벤트 중 택1
- 결과 안내: 채널 메시지, 스레드, DM

가장 안정적인 MVP는 `슬래시 커맨드 + 모달 + DB 저장`이다.

### 3. 유저를 장기간 추적할 수 있는가?

가능하다.

- Discord 유저 ID는 고유 식별자로 사용할 수 있다.
- 서버별 운영이면 `guild_id + user_id` 조합으로 관리하면 된다.
- 닉네임은 바뀔 수 있으므로 기본 키로 쓰면 안 된다.

### 4. 메시지 인증 방식도 가능한가?

가능하지만 제약이 있다.

- 메시지 내용 자체를 읽으려면 `MESSAGE_CONTENT` privileged intent 이슈를 고려해야 한다.
- 반응 기반 체크는 `GUILD_MESSAGE_REACTIONS` intent 로 처리 가능하다.
- 메시지 파싱 방식은 오탐/누락 관리가 필요하다.

따라서 MVP에서는 메시지 내용 감시보다 **명시적 커맨드 방식**이 더 안전하다.

### 5. 일요일 주간 정산은 가능한가?

가능하다.

- Discord가 우리 앱 대신 주간 정산을 실행해주지는 않는다.
- 우리 서버에서 스케줄러를 돌려 일요일마다 DB를 집계한 뒤 결과를 채널에 전송하면 된다.

## MVP 권장 흐름

### 주간 계획

1. 사용자가 `/주간계획` 실행
2. 모달에서 이번 주 목표 입력
3. 봇이 DB에 `week_start`, `goal_text`, `target_count` 저장
4. 저장 완료 메시지 전송

### 일일 인증

1. 사용자가 `/인증` 실행
2. 오늘 수행 내용 또는 링크/메모 입력
3. 봇이 해당 주간 계획과 연결해서 인증 기록 저장
4. 하루 1회만 인정할지, 여러 회 허용할지 정책 적용

### 주간 리더보드

1. 매주 일요일 스케줄러 실행
2. 이번 주 계획 대비 인증 수를 집계
3. 달성률 계산
4. 서버 채널에 순위표 전송

## 현재 권장 구현 방향

- Discord는 인터페이스 계층으로 사용
- 앱 서버에서 비즈니스 로직 처리
- DB에 사용자/계획/인증 기록 저장
- 일요일 스케줄러로 주간 집계
- MVP는 커맨드 중심으로 단순하게 시작

## 최종 아키텍처 결정

이번 프로젝트의 초기 아키텍처는 다음으로 확정한다.

- Cloudflare Workers
- Cloudflare D1
- Cloudflare Cron Triggers
- Discord Application Interactions

즉, 이 프로젝트는 `24시간 상주하는 Gateway 봇`이 아니라, `Discord를 UI로 사용하는 서버리스 스터디 관리 앱`으로 설계한다.

## 왜 이 구조를 선택하는가

### 비용

- 24시간 서버를 따로 두지 않아도 된다.
- 요청이 있을 때만 Worker가 실행된다.
- 정해진 시간 작업은 Cron Trigger가 실행한다.
- 소규모 스터디 기준으로 무료 한도 안에서 운영 가능성이 높다.

### 운영 단순성

- 봇 서버 프로세스를 계속 켜둘 필요가 없다.
- 서버 sleep, 재시작, 프로세스 죽음 같은 전통적 운영 이슈가 적다.
- 스케줄러를 외부 서비스에 따로 붙이지 않아도 된다.

### 기능 적합성

- 주간 계획 입력: Interaction 처리로 충분
- 매일 인증: Interaction 처리로 충분
- 주간/일간 리마인더: Cron Trigger로 충분
- 리더보드 집계: D1 쿼리로 충분

## 시스템 구성

### 1. Discord

역할:

- 사용자의 입력 창구
- 알림과 결과 표시 창구

사용 요소:

- Slash Commands
- Buttons
- Modals
- 채널 메시지

### 2. Cloudflare Worker

역할:

- Discord Interaction Webhook 수신
- 명령어/버튼/모달 처리
- 비즈니스 로직 실행
- D1 읽기/쓰기
- Discord 응답 전송

### 3. Cloudflare D1

역할:

- 사용자 정보 저장
- 주간 계획 저장
- 일일 인증 저장
- 리더보드 계산용 데이터 저장
- 설정값 저장

### 4. Cloudflare Cron Triggers

역할:

- 매일 계획/인증 리마인더 실행
- 매일 또는 매주 리더보드 집계 실행
- 자동 정산 메시지 전송

## 상호작용 방식 결정

MVP에서는 일반 메시지 감시보다 **명시적 상호작용 중심**으로 간다.

이유:

- `MESSAGE_CONTENT` privileged intent 의존도를 피할 수 있다.
- 사용자의 행동 흐름이 명확하다.
- 검증 로직이 단순해진다.
- 서버리스 구조와 잘 맞는다.

## MVP 사용자 흐름

### A. 주간 계획 작성

1. 매주 월요일 오전 정해진 시간에 봇이 계획 작성 안내 메시지를 보낸다.
2. 메시지에는 `계획 작성` 버튼이 있다.
3. 버튼을 누르면 모달이 열린다.
4. 사용자는 이번 주 목표 내용과 목표 횟수를 입력한다.
5. Worker가 D1에 저장한다.
6. 저장 완료 응답을 보낸다.

대체 입력 방식:

- `/주간계획` 슬래시 커맨드 실행
- 모달 또는 커맨드 옵션으로 직접 입력

### B. 일일 인증

1. 매일 밤 정해진 시간에 봇이 인증 안내 메시지를 보낸다.
2. 메시지에는 `오늘 인증` 버튼이 있다.
3. 버튼을 누르면 모달이 열린다.
4. 사용자는 오늘 수행한 내용, 링크, 메모를 입력한다.
5. Worker가 해당 주간 계획과 연결해서 D1에 저장한다.
6. 저장 완료 응답을 보낸다.

대체 입력 방식:

- `/인증` 슬래시 커맨드 실행

### C. 리더보드

초기 단계:

- `/리더보드` 실행 시 실시간 계산 후 응답

자동화 단계:

- Cron Trigger가 매일 또는 매주 지정 시각에 집계
- 채널에 자동 게시

## 스케줄 정책 초안

아직 확정 전이지만 기본안은 다음과 같다.

- 월요일 09:00: 이번 주 계획 작성 안내
- 화요일~일요일 21:00: 오늘 인증 리마인더
- 매일 23:00: 당일 인증 마감 안내 또는 당일 현황 요약
- 일요일 23:00: 주간 리더보드 및 달성률 발표

주의:

- Cloudflare Cron은 UTC 기준으로 동작하므로, 한국 시간 기준 스케줄을 계산해서 설정해야 한다.

## 비즈니스 규칙 초안

- 기준 타임존은 기본적으로 `Asia/Seoul`
- 한 주는 `월요일 시작`, `일요일 종료`
- 한 사용자는 한 주에 하나의 활성 계획만 가진다
- 하루 인증은 기본적으로 하루 1회만 인정한다
- 인증은 해당 주의 활성 계획에 연결된다
- 리더보드는 `인증 횟수 / 목표 횟수` 기반 달성률로 계산한다
- 목표 횟수가 같은 경우 인증 개수, 인증 시간이 보조 정렬 기준이 될 수 있다
